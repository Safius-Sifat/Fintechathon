# Mobile build (Android dev client)

How to build and run `apps/mobile` as an Expo development build. Expo Go is not supported: the app is meant to load native modules.

## Pins

| Item                               | Version                                   |
| ---------------------------------- | ----------------------------------------- |
| Expo SDK / React Native / React    | 54.0.33 / 0.81.5 / 19.1.0                 |
| Node / pnpm                        | 22.23.3 / 10.20.0 (via `scripts/pnpm.sh`) |
| JDK                                | 17                                        |
| Android compile / target / min SDK | 36 / 36 / 31                              |
| NDK                                | 27.1.12297006                             |
| Gradle                             | 8.14.3 (wrapper from prebuild)            |
| Trust Wallet Core (Android)        | `com.trustwallet:wallet-core:4.8.4`       |

`android/` is generated by `expo prebuild` (Continuous Native Generation) and is not committed. Native changes go through `app.json` plugins or `modules/owner-wallet`.

## Wallet Core download credentials

Wallet Core's Android artifact is published on GitHub Packages, which needs a GitHub token even for public packages. Create a classic personal access token with only the `read:packages` scope and give it to Gradle in one of two ways:

- `~/.gradle/gradle.properties` (outside the repository): `gpr.user=<github username>` and `gpr.key=<token>`
- environment variables `GPR_USER` and `GPR_KEY`

This is a build credential only. It is never committed, never put in `app.json` and never shipped in the app. `modules/owner-wallet/app.plugin.js` adds the repository to the generated project and restricts it to the `com.trustwallet` group; that group resolves from nowhere else.

## Steps

```sh
sh scripts/pnpm.sh install --frozen-lockfile
cd apps/mobile
npx expo prebuild --platform android --no-install
cd android
./gradlew assembleDebug -PreactNativeArchitectures=x86_64   # arm64-v8a for phones
adb install -r app/build/outputs/apk/debug/app-debug.apk
cd .. && npx expo start --dev-client
```

`expo prebuild` adds an `"ios": "expo run:ios"` script to `apps/mobile/package.json`. Remove only that line; check `git diff apps/mobile/package.json` rather than restoring the whole file, so other edits are kept.

Set `ANDROID_HOME` (or `sdk.dir` in `android/local.properties`) to the Android SDK.

## Native module tests

```sh
cd apps/mobile/android
./gradlew :owner-wallet:connectedDebugAndroidTest -PreactNativeArchitectures=x86_64
```

Runs `modules/owner-wallet/android/src/androidTest` on the connected device or emulator. Emulator runs are local results only; physical-phone acceptance needs a real device.

## Windows: long paths

The C++ build of `expo-modules-core` and `react-native-screens` produces object paths longer than 260 characters under pnpm's isolated `node_modules` layout. The `ninja` bundled with SDK CMake 3.22.1 and 3.30.5 (1.10.2) cannot create them, so the build fails with `ninja: error: mkdir(...)`.

Fix (local machine only, no repository change):

1. Enable long paths: `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem\LongPathsEnabled = 1`.
2. Install SDK CMake 3.31.6, which bundles ninja 1.12.1:
   `sdkmanager --install "cmake;3.31.6"`.
3. Point the generated project at it in `apps/mobile/android/local.properties` (git-ignored; re-add after `prebuild --clean`):

   ```properties
   sdk.dir=C\:/Users/<you>/AppData/Local/Android/Sdk
   cmake.dir=C\:/Users/<you>/AppData/Local/Android/Sdk/cmake/3.31.6
   ```

Linux and macOS hosts do not need this.

## Font scale

`plugins/withFontScaleLayout.js` enables React Native's `enableFontScaleChangesUpdatingLayout` flag (off by default in 0.81.5), keeping every other Stable flag. Without it, changing the system font size while the app is running leaves text clipped until restart. Revisit when upgrading React Native.
