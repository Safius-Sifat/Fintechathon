# Infrastructure boundary

`compose.dev.yaml` starts local Postgres, authenticated NATS/JetStream and ephemeral Consul discovery. Ports bind127.0.0.1. Consul dev mode has no production ACL/TLS configuration and is never a release deployment. NATS credentials are local only. Preserve Postgres/NATS named volumes; `infra:down` does not delete them.

MPC nodes are intentionally not configured with example passwords/keys or auto-started. Person2 must implement the pinned **three-node PoC** on the existing 4 GiB Azure VM: three MPCium containers with separate node identities and encrypted persistent share volumes, `thresholdConfig: 1`, and two required signing participants. All three join DKG; any two are the intended signing quorum. This single-VM layout proves integration and quorum behavior only. It does not provide independent host-compromise protection. See Person2's P2-01/P2-06 runbook. `pnpm mpc:fetch` fetches source only. Source download does not establish MPC readiness.

The competition deployment uses one VM because the team has accepted the shared-host PoC boundary. Keep the API public endpoint on HTTPS; bind MPC nodes, NATS and Consul to a private Docker network. Because the current API uses host networking, bind any host-to-container NATS/Consul ports to `127.0.0.1` only; keep all management/service ports off the public interface. Give each node a distinct identity, password, volume and backup. Protect secrets outside Git and images. Pin release images by verified digests in the deployment manifest. Three containers on one VM are three protocol participants, not three independent security domains.
